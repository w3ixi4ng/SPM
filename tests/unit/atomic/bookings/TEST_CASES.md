# Test cases — bookings service (unit)

Covers `tests/unit/atomic/bookings/test_app.py`, `test_decision.py` and
`test_availability.py` (S-30): the atomic service that owns
venue booking requests (`bookings.bookings`). It stores and lists them and
records final decisions for S-37; deletion is not exposed. It never
calls another service, and it never judges whether a request is suitable.
The `venue_bookings` composite does that before it writes here. Supabase is
replaced with a `MagicMock` through `app.dependency_overrides[get_db]`, so
there is no network, database, or Docker.

Kong has no direct entry for this service. Create/list retain their internal
contract. S-37 decision calls independently verify the session and staff role,
including direct calls to the published port; these checks are tested below.

## S-38 confirmed specifications

Story: S-38 Prevent Overlapping Booking Confirmation.
Confirmed by the developer on 2026-09-29. Back-to-back bookings are allowed.

> **Superseded in part by S-76 (2026-10-09).** Where S-38 and S-76 differ,

## S-30 — view venue availability calendar

Story: S-30 View venue availability calendar.
Confirmed by the developer on 2026-09-30. Executed locally on 2026-09-30.

S-30 extends this service in four ways, each following an existing pattern:

- **Holds.** A `pending` request becomes an exclusive tentative hold. The
  S-38 overlap check (`_overlap`, and the exclusion constraint behind it) now
  covers `pending` as well as `confirmed` rows, and runs on `POST /bookings`
  as well as on approval.
- **Blocks.** A new `bookings.blocks` table records whole-day periods Venue
  Staff mark a venue unavailable. Adding or removing a block checks the staff
  session in this service, as S-37 decisions do (`require_venue_staff`).
- **Conflict messages.** These use S-38's `_conflict_detail` format.
- **Listing.** A venue plus a date range is one more filter on the existing
  always-filtered `GET /bookings`. `GET /blocks` takes the same filter.

**Shared test data.** Studio B is `bbbbbbbb-bbbb-4bbb-8bbb-bbbbbbbbbbbb` and
Studio C is `cccccccc-0000-4ccc-8ccc-cccccccccccc`. Venue Staff is
`abababab-abab-4bab-8bab-abababababab`. The existing booking is on Studio B,
`2026-11-12`, `10:00`–`12:00`.
